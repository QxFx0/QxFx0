document inventories the subsystem, determines its integration status, and

## Assessment

### What Works

1. The subsystem is well-structured: clear separation between hand-authored
   content (`Semantic/Content/`), selection logic (`ContentSelector/`), and
   auto-generated lexicon (`GeneratedLexicon.hs`).
2. Test coverage is broad — 10 test suites cover the main modules.
3. The B3 gate concept (definition + distinction predicates) is sound.
4. Integration is clean — Content modules are imported, not duplicated.

### What's Missing

1. **No ADR** — the subsystem was built without architectural review.
2. **No quality gate** — tests verify mechanics, not content quality.
   There are no golden tests that check whether the output is philosophically
   meaningful.
3. **No coverage boundary** — the 9 seed topics are hardcoded; there is no
   documented expansion strategy.
4. **Generated lexicon is opaque** — 84,971 LOC in a single file with no
   documented regeneration process or validation.

## Recommendations

1. **Write ADR-0049** for the Content/GeneratedLexicon subsystem. Document:
   - Why it was built (B3 gate requirement)
   - What alternatives were considered (LLM, external KB, hand-authored)
   - What the quality gate is (golden tests + coverage criteria)
   - How the generated lexicon is regenerated and validated

2. **Add content quality gate** (P2 item): golden tests that verify:
   - Definition predicates are non-tautological for each covered topic
   - Distinction predicates are specific to each topic pair
   - Output is philosophically meaningful (not just syntactically valid)

3. **Document generated lexicon pipeline**: `scripts/build_input_lexicon.py`
   must be in CI, with a documented regeneration and validation process.

4. **Mark experimental**: Until ADR-0049 is accepted and quality gates are
   in place, the Content subsystem should be marked experimental in Haddock.

## Conclusion

The Content/GeneratedLexicon subsystem is **actively integrated into
production** with broad test coverage, but lacks an ADR and content quality
gate. It is not dead code — it is live code without architectural governance.
The immediate action is to write ADR-0049 and add content quality gates.
