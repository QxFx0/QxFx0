## Вердикт по аудиту («согласен / спорю / дополняю»)

**Согласен с телом аудита.** Диагнозы P0 воспроизводятся по коду
точь-в-точь; выборочные проверки P1/P2 тоже сошлись.

**Спорю в двух местах:**

1. **Порядок фиксов.** Предложенный порядок («п.1 → п.3 → п.5»)
   ставит первым редкий каскадный баг, а следом — регулярный и
   дешёвый. Меняю: **п.5 (кризисные гейты) первым**. Это
   (а) safety-инвариант: жёсткий лексический гейт не должен иметь
   обходных путей ни при каком состоянии деградации; (б) фикс
   локален — кризисная проверка добавляется только на пути,
   которые и так не выполняют пайплайн, и не трогает нормальный
   путь (детекция в `Effects.hs:730–731` и персистенция остаются
   как есть). Далее п.1, п.3, затем персистентность (п.6/7/8),
   затем решение по п.4.
2. **Способ фикса п.1.** Аудит прав в диагнозе, но толерантности в
   валидаторе недостаточно. Предлагаю структурный вариант:
   **коллапс супервенит коммитмент** — при `mCollapse = Just` сырой
   результат `computeNextEssence` не доходит до precommit/валидатора:
   канонический сброс (`collapseEssenceAt`) выполняется единожды, а
   сырой триггер отбрасывается, поэтому пара `(Есть триггер,
   Uncommitted-после-сброса)` не рождается вовсе; траектория
   свидетеля остаётся доступной калибровке (адаптация — свойство
   траектории, не порядка сброса). `computeEssenceValidation`
   остаётся fail-closed для настоящего `(Just trigger,
   Uncommitted)` без сброса в этом же ходу. Сохраняются оба
   инварианта BD2: сброс виден (`selfLastEssenceResetEvent` →
   `trcEssenceResetEvent`) и «сброс либо виден, либо его не было».

## P0 — критические

**п.1. EssenceRupture на commit+коллапсе одного хода.**
Вердикт: `ПОДТВЕРЖДЕНО`. Пути и строки аудита сходятся:
`computeNextEssence` может вернуть `(EssenceCommitted …, Just trigger)`
(`Finalize/State.hs:404–413`), Phase F в том же ходу сбрасывает
Essence через `collapseEssenceAt` (`:735–743`), `computeEssenceValidation`
(`:208–217`) видит `(Just _, EssenceUncommitted _)` → `Left`,
`Precommit.hs:221–226` прокидывает, `Commit.hs:93–96` бросает
`EssenceRupture`; Engine возвращает предходовое состояние
(`Engine.hs:77–83, 209–213`) и теряет ход вместе с
`EssenceResetEvent`. Условия достижимы: `shouldCommit` — angst ≥ 0.75
**или** полное окно из 8 свидетелей с `ewConatusScalar < 7.0`
(`Self/Essence.hs:330–343`); `mCollapse` — `StanceDoubted ∧
conatus < floor` (`Semantic/Stance.hs:175–178`). Комбинация не
покрыта ни одним тестом (SelfEssenceCommit и EssenceCollapse
проверяют половины отдельно).
Статус: `исправлено 2026-10-17` (коммит `911151c`, батч 1).
Действие: «коллапс супервенит коммитмент» (см. спор 2). Бар:
пре-регистрация (2); лендинг — CALIBRATION_REPORT (2).

**п.2. Два из четырёх детекторов аномалий мертвы, третий игнорирует
аргумент.** Вердикт: `ПОДТВЕРЖДЕНО` (+ `УТОЧНЕНО` про ложное
покрытие). Единственная запись в `ssStances`/`ssStanceLineages` —
инициализация `M.empty` (`Runtime/StateDefaults.hs:342,345`); живое
зеркало — `ssStanceDefenses` (`Finalize/State.hs:725–729`).
`antiConatusMove` игнорирует `_family` (`Anomaly.hs:97`); тесты
передают `undefined` (`Test/Suite/Anomaly.hs:279–307`).
Статус: `решено (2026-10-17) — ревайв`. AntiConatus читает
`ssStanceDefenses` по топику и использует сигнал family; тесты с
`undefined` заменяются на реальные фикстуры. Подвопрос при входе в
батч: Temporal — рантайм-источника lineage нет; либо минимальный
журнал в Finalize, либо честный ретайр детектора с
документированием (пре-регистрация — на выбранный вариант).
Замечание: до решения `Types/Thresholds/Anomaly.hs` документирует
часть ворот, недостижимых в рантайме — это фиксируется в шапке
модуля.

**п.3. Self-ref коллапс — substring-матчинг.**
